# 类别 1：📄 文本处理与信息收敛

> **核心价值**：将海量非结构化信息转化为可操作的洞察
> **典型用户**：研究员、分析师、项目经理、知识工作者
> **技术特点**：利用大上下文窗口（可处理500页文档）和文档理解能力

## 场景 1：长文档摘要提取

### 🎯 典型问题场景
面对200页的供应商合同、行业研究报告或学术论文，人工阅读耗时5-10小时，且容易遗漏关键信息。需要快速掌握核心内容以支持决策。

### 💡 Claude Code 解决方案
利用Claude Code的大上下文窗口（支持500页文档），可一次性处理完整文档并按照自定义维度提取关键信息。相比传统方法，可将阅读时间压缩至10分钟，且结构化输出便于后续引用。

### 📋 实操步骤提示词模板

**步骤 1：准备材料**
- 待分析的PDF/Word文档（保存到本地）
- 明确需要提取的信息维度（如：核心观点、数据证据、风险点等）

**步骤 2：核心提示词**
```
我需要你分析这份文档：[文档路径/粘贴文本]

请按以下结构提取关键信息：

1. **执行摘要**（200字以内）
   - 文档类型和主题
   - 核心结论/建议

2. **关键发现**（5-8个要点）
   - 每个要点包含：发现内容 + 支撑数据/页码

3. **重要数据**
   - 关键数字指标
   - 时间节点
   - 涉及金额/百分比

4. **风险/注意事项**（如有）
   - 潜在问题点
   - 需要进一步核实的内容

5. **行动建议**
   - 基于文档内容的下一步行动清单

输出格式：Markdown，每个部分使用清晰的标题和列表。
```

**步骤 3：结果优化**（针对特定需求）
```
请针对以下受众调整摘要：
- 目标读者：[如：公司高管/技术团队/法务部门]
- 侧重点：[如：财务影响/技术可行性/法律风险]
- 字数限制：[如：500字以内/2页PPT大纲]
```

### 👥 适用人群标签
`#分析师` `#项目经理` `#研究员` `#投资人` `#新手友好` 🟢

### 💼 真实应用案例
某咨询公司使用此方法处理客户提供的150页行业报告，从原本需要2天的人工阅读缩短至30分钟，并自动生成可直接用于客户汇报的PPT大纲。

## 场景 2：多源信息对比分析

### 🎯 典型问题场景
竞品调研时需要对比5-10家公司的产品说明、定价策略、用户评价，人工整理表格耗时且容易出错，难以发现跨文档的关联模式。

### 💡 Claude Code 解决方案
Claude Code可同时处理多个文档，自动提取相同维度的信息并生成对比矩阵。支持从网页、PDF、Excel等多种格式中抽取数据，统一呈现差异化特征。

### 📋 实操步骤提示词模板

**步骤 1：准备材料**
- 收集所有待对比的文档（保存在同一文件夹）
- 列出对比维度（如：价格、功能、目标用户、技术架构等）

**步骤 2：核心提示词**
```
我需要对比以下资料中的竞品信息：
[文档1路径]
[文档2路径]
[文档3路径]
...

对比维度：
1. 产品定位
2. 核心功能（列表形式）
3. 定价策略
4. 目标客户群
5. 技术特点
6. 市场优势/劣势

请输出为Markdown表格，格式如下：
| 对比维度 | 竞品A | 竞品B | 竞品C | 我方产品 |
|---------|-------|-------|-------|----------|
| ...     | ...   | ...   | ...   | ...      |

在表格后补充：
- **差异化洞察**：竞品之间的显著差异
- **市场空白点**：所有竞品都未覆盖的需求
- **我方定位建议**：基于对比分析的战略建议
```

**步骤 3：深度分析**
```
基于上述对比，请进一步分析：
1. 如果我们定价为[具体金额]，在市场中的竞争力如何？
2. 竞品A的[某功能]用户评价最高，我们如何差异化？
3. 生成一份3分钟演讲稿，向投资人说明我们的独特价值。
```

### 👥 适用人群标签
`#产品经理` `#市场研究` `#战略分析` `#创业者` `#进阶` 🟡

### 💼 真实应用案例
某SaaS创业公司用此方法对比8个竞品的定价页面和功能文档，发现"中小企业<50人"细分市场的定价空白，调整策略后转化率提升40%。

## 场景 7：文本数据清洗与标准化

### 🎯 典型问题场景
从多个系统导出的客户数据格式不统一（如电话号码有带区号/不带区号/带空格，公司名称有"有限公司""股份有限公司"等变体），需要标准化后导入CRM系统。

### 💡 Claude Code 解决方案
Claude Code可识别数据模式，自动统一格式、纠正错别字、合并重复项、标注异常值，并生成数据质量报告。支持CSV、Excel等格式的批量处理。

### 📋 实操步骤提示词模板

**步骤 1：准备材料**
- 待清洗的数据文件（CSV/Excel）
- 数据标准化规则（如：电话号码统一为11位不带空格）

**步骤 2：核心提示词**
```
请清洗以下数据文件：[文件路径]

清洗规则：

1. **电话号码**
   - 统一格式：11位纯数字（去除空格、短横线、括号）
   - 补全缺失的区号（默认+86）
   - 标记无效号码（非11位或包含字母）

2. **公司名称**
   - 统一后缀：将"有限公司""股份有限公司""股份公司"统一为"有限公司"
   - 去除前后空格
   - 标注疑似重复（如"阿里巴巴"和"阿里巴巴网络技术"）

3. **邮箱地址**
   - 转换为小写
   - 验证格式有效性
   - 标记疑似企业邮箱/个人邮箱

4. **日期格式**
   - 统一为YYYY-MM-DD格式
   - 标记无法解析的日期

5. **地址信息**
   - 提取省/市/区
   - 标准化行政区划名称（如"北京市朝阳区" vs "朝阳区"）

输出：
1. 清洗后的数据文件（新文件名加"_cleaned"）
2. 数据质量报告：
   - 处理记录总数
   - 修正条目数（按类别）
   - 异常数据清单（需人工核查）
   - 疑似重复记录
```

**步骤 3：验证与导入**
```
请生成SQL/Python脚本，将清洗后的数据导入数据库：
- 表名：[指定]
- 字段映射：[CSV列名 → 数据库字段名]
- 冲突处理：如主键重复则[跳过/更新/报错]
```

## 场景 8：知识库文档去重与整合

### 🎯 典型问题场景
公司知识库经过3年积累有500+份文档，存在大量重复或过时内容（如同一个问题有5个版本的解答），查找信息效率低且容易误导新员工。

### 💡 Claude Code 解决方案
Claude Code可分析所有文档的语义相似度，识别重复/冗余内容，提取各版本的差异点，生成整合建议和标准化文档框架。

### 📋 实操步骤提示词模板

**步骤 1：准备材料**
- 知识库文档目录（支持Markdown、Notion导出、Confluence导出等）
- 文档分类标签（如有）

**步骤 2：核心提示词**
```
知识库路径：[文件夹路径]
文档总数：[数量]

请执行知识库清理：

1. **重复内容识别**
   - 找出语义相似度>80%的文档对
   - 分类重复类型：
     * 完全重复（建议删除）
     * 部分重复（建议合并）

2. **内容质量评估**

   分析现有文档覆盖的主题，列出：

1. 重复文档对照表（CSV）
2. 文档质量评分表
3. 整合行动计划（分优先级）
4. 新建文档主题清单
```

## 场景 9：历史资料归档索引生成

### 🎯 典型问题场景
公司有10年的项目资料（包括设计稿、会议记录、合同等）分散在各个文件夹，命名不规范，需要建立可搜索的索引系统方便日后查找。

### 💡 Claude Code 解决方案
Claude Code可遍历文件系统，读取文档元数据和内容摘要，生成结构化索引（包含关键词、时间、项目、相关人员等维度），支持导出为数据库或搜索引擎格式。

### 📋 实操步骤提示词模板

**步骤 1：准备材料**
- 历史资料存放路径
- 索引字段定义（如：项目名、时间、文档类型、关键参与人等）

**步骤 2：核心提示词**
```
请为以下路径的历史资料建立索引：[根目录路径]

索引要求：

1. **文件扫描**
   - 遍历所有子文件夹
   - 支持的文件类型：PDF, Word, Excel, PPT, Markdown, 图片（提取EXIF）
   - 记录文件元数据：创建时间、修改时间、大小、路径

2. **内容分析**
   对每个文件提取：
   - 文档摘要（50字以内）
   - 文档类型（合同/报告/设计稿/会议记录等）
   - 关键词（5-10个）
   - 提及的人名、公司名、项目名
   - 时间信息（文档内提及的日期）

3. **智能分类**
   根据内容和文件名推断：
   - 所属项目（如文件名包含项目代号）
   - 业务条线（研发/销售/人力等）
   - 保密级别（如包含"内部""机密"等关键词）

4. **索引输出**
   生成三种格式：
   - **Excel索引表**：所有字段可筛选排序
   - **Markdown目录**：按项目/时间分层展示
   - **JSON数据**：可导入搜索引擎（如Elasticsearch）

索引表字段：
| 文件名 | 路径 | 类型 | 项目 | 时间 | 关键词 | 摘要 | 相关人员 | 创建日期 | 文件大小 |

附加功能：
- 标记疑似重复文件（文件名相似或内容hash相同）
- 标记超过[X年]的文件（建议归档或删除）
- 生成资料分布统计（按年份/项目/类型）
```

**步骤 3：搜索功能实现**
```
基于上述索引，创建一个简单的搜索脚本：
- 输入：关键词/项目名/时间范围
- 输出：匹配的文件列表（按相关度排序）
- 支持模糊搜索和多条件组合
```

### 👥 适用人群标签
`#档案管理` `#项目经理` `#法务` `#行政` `#专家级` 🔴

## 场景 10：专业术语库自动提取与解释

### 🎯 典型问题场景
新员工入职后需要学习大量行业/公司特有术语（如内部项目代号、技术缩写、业务黑话），现有文档分散且缺少统一的术语表，学习成本高。

### 💡 Claude Code 解决方案
从公司内部文档、会议记录、邮件中自动提取高频术语，结合上下文生成解释，构建结构化术语库并支持多种输出格式（Wiki、Notion、Glossary插件等）。

### 📋 实操步骤提示词模板

**步骤 1：准备材料**
- 公司内部文档集合（至少50份以上，覆盖不同部门）
- 已知术语清单（可选，用于优先级排序）

**步骤 2：核心提示词**
```
请从以下文档集合中提取并解释专业术语：[文件夹路径/粘贴文档]

提取规则：

1. **术语识别**
   优先提取：
   - 大写缩写（如：KPI, OKR, MVP）
   - 频繁出现的专有名词（出现≥5次）
   - 行业特有表达（与通用词汇含义不同的词）
   - 公司内部代号（项目名、系统名等）

2. **解释生成**
   对每个术语提供：
   - **中文全称**（如适用）
   - **英文全称**（如适用）
   - **定义**（50字以内，通俗易懂）
   - **使用场景**：该术语常出现在什么情境
   - **相关术语**：关联的其他术语
   - **示例句子**：从原文档中提取1-2个使用示例

3. **分类组织**
   按以下类别分组：
   - 业务流程类（如：POC、RFP）
   - 技术架构类（如：微服务、API Gateway）
   - 管理方法类（如：Scrum、Sprint）
   - 公司特有类（内部系统/项目代号）
   - 行业通用类

4. **输出格式**
   生成以下三种版本：

   **版本1：新人手册（Markdown）**
   ```
   # 公司术语速查手册

   ## 业务流程类
   ### POC (Proof of Concept)
   - **中文**：概念验证
   - **定义**：...
   - **使用场景**：...
   - **示例**："我们需要在下周完成POC..."
   ```

   **版本2：快速索引（表格）**
   | 术语 | 全称 | 定义 | 类别 | 使用频率 |

   **版本3：交互式问答**
   可用于聊天机器人的Q&A格式：
   Q: POC是什么意思？
   A: POC是Proof of Concept的缩写...
```

**步骤 3：持续更新机制**
```
设计一个术语库维护流程：
1. 如何新增术语（模板）
2. 如何更新定义（版本控制）
3. 定期从新文档中扫描新术语的脚本
```

### 👥 适用人群标签
`#HR` `#培训专员` `#知识管理` `#团队leader` `#进阶` 🟡
