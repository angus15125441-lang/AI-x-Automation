# 定制方案设计

本文档包含三个不同层级的灵感管理自动化方案设计。

---

## 方案概览

- **方案A**: 轻量级方案（Claude Code + Markdown）
- **方案B**: 混合方案（第三方工具 + Claude Code）
- **方案C**: 深度自动化方案（自建脚本 + API集成）

---

## 方案A：Claude Code + Markdown（轻量级）

### 核心理念

用Claude Code处理内容，Markdown存储知识，Git版本管理，无需额外工具或服务。完全基于本地文件系统，保持数据完全可控。

### 工作流程（5步）

1. **收集** - 发现灵感时，复制URL或内容文本到Claude Code
2. **处理** - 使用预设Prompt模板，Claude自动提取：标题、摘要、关键要点、标签、应用场景
3. **归档** - Claude自动生成Markdown文件，保存到 `inspiration/YYYY-MM/topic-name.md`
4. **索引** - 自动更新 `inspiration/index.md`，添加新条目（按时间和主题）
5. **回顾** - 每周运行回顾Prompt，Claude生成「本周灵感总结」到 `inspiration/weekly/YYYY-WW.md`

### 所需文件结构

```
inspiration/
├── index.md                          # 主索引（按主题分类）
├── chronological-index.md            # 时间线索引（按日期）
├── 2024-11/                          # 按月归档
│   ├── ai-automation-tools.md
│   ├── code-architecture-patterns.md
│   └── workflow-optimization.md
├── 2024-12/
│   └── ...
├── weekly/                           # 每周总结
│   ├── 2024-W46.md
│   └── 2024-W47.md
└── templates/
    ├── inspiration-template.md       # 灵感条目模板
    └── weekly-summary-template.md    # 周总结模板
```

### 核心Prompt模板

**日常收集Prompt：**

```
我发现了一个灵感素材：

[粘贴URL或内容描述]

请帮我：
1. 提取核心信息（50-100字摘要）
2. 提炼3-5个关键要点（bullet points）
3. 生成3-5个关键词标签
4. 标注适用场景（如：AI工具开发、工作流优化、技术架构等）
5. 建议后续行动（如有）

然后按以下模板格式生成Markdown文件：

---
标题: [自动提取]
来源: [URL]
日期: 2024-11-17
类型: [文章/视频/工具/对话]
标签: #tag1 #tag2 #tag3

## 核心内容
[摘要]

## 关键要点
- 要点1
- 要点2
- 要点3

## 应用场景
- 场景1: [具体描述]
- 场景2: [具体描述]

## 后续行动
- [ ] 行动项1（如有）
---

请将文件保存到 `inspiration/2024-11/[自动命名].md`，
并在 `inspiration/index.md` 中添加索引条目。

执行后告诉我文件路径。
```

**每周回顾Prompt：**

```
请分析 `inspiration/2024-11/` 目录下本周新增的灵感条目。

生成每周总结，包括：
1. 本周收集了多少条灵感
2. Top 3 最有价值的发现
3. 主题分布（按标签统计）
4. 推荐优先行动的3个后续任务

保存到 `inspiration/weekly/2024-W47.md`
```

### 优点（3个）

✅ **完全免费** - 零月度成本，只依赖已有工具（Claude Code + Git）

✅ **完全可控** - 数据存储在本地，Markdown纯文本格式，永不锁定，可随时迁移

✅ **无缝集成** - 与现有开发workflow完全融合，在Claude Code中直接操作，无需切换工具

### 缺点（3个）

❌ **需要手动触发** - 每次收集灵感需要手动复制内容到Claude Code并运行Prompt

❌ **没有自动导入** - 无浏览器插件快速保存，无法从RSS/邮箱自动抓取

❌ **需要自律维护** - 依赖个人习惯，容易因忘记而中断

### 预估工作量

- **初始搭建**：2小时
  - 创建文件结构：15分钟
  - 设计模板和Prompt：1小时
  - 测试优化：45分钟

- **日常使用**：每条灵感30秒-1分钟
  - 复制内容：5秒
  - 粘贴Prompt：5秒
  - Claude处理：10-20秒
  - 确认保存：10秒

- **每周维护**：10-15分钟
  - 运行周总结Prompt：5分钟
  - 审查并调整：5-10分钟

## 方案B：Omnivore + Claude Code（混合方案）

### 核心理念

用Omnivore做收集入口（利用其浏览器插件和稍后读功能），Claude Code做深度处理和知识结构化。结合第三方工具的便利性与自有系统的可控性。

### 工作流程（6步）

1. **收集** - 浏览网页时点击Omnivore浏览器插件一键保存（秒级操作）
2. **初筛** - 阅读时在Omnivore中高亮关键段落，添加简短笔记
3. **导出** - 每周从Omnivore导出高亮内容为Markdown（内置功能）
4. **处理** - 将导出的Markdown粘贴到Claude Code，运行批处理Prompt
5. **归档** - Claude自动提取关键信息，分类后写入本地知识库 `inspiration/`
6. **回顾** - Claude生成每周总结，整合Omnivore高亮与本地知识库

### 所需工具

- **Omnivore**（免费，开源）
  - 浏览器插件：Chrome/Firefox/Safari
  - 功能：一键保存文章、高亮、笔记、邮箱转发

- **Claude Code**（已有）
  - 功能：批量处理、信息提取、知识结构化

- **文件系统**
  - 与方案A相同的 `inspiration/` 目录结构

### 核心Prompt模板

**每周批处理Prompt：**

```
我从Omnivore导出了本周的阅读高亮内容（见下方）。

请帮我：
1. 按主题自动分组（AI工具、工作流优化、技术架构、其他）
2. 每组提取Top 3最有价值的片段
3. 为每个片段添加：
   - 50字摘要
   - 3-5个标签
   - 应用场景
4. 生成结构化Markdown文件：
   - 单条灵感保存到 `inspiration/2024-11/[主题名].md`
   - 周总结保存到 `inspiration/weekly/2024-W47.md`
5. 更新 `inspiration/index.md` 索引

---
[粘贴Omnivore导出的Markdown内容]
---

完成后列出创建的文件清单。
```

**单条快速处理Prompt（可选）：**

```
这是我从Omnivore中标记的一篇文章的高亮内容：

标题: [文章标题]
来源: [URL]
高亮片段:
- [片段1]
- [片段2]
- [片段3]

请提取核心价值并保存为灵感条目。
```

### 优点（3个）

✅ **自动收集便捷** - 浏览器插件一键保存，邮箱转发自动导入，无需中断阅读流程

✅ **免费且开源** - Omnivore完全免费，数据可导出，避免供应商锁定

✅ **保留深度处理** - Claude Code仍负责核心价值提取，维持知识质量

### 缺点（3个）

❌ **仍需手动触发处理** - 虽然收集自动化，但每周批处理仍需手动运行Prompt

❌ **跨工具操作** - 需要在Omnivore和Claude Code之间切换，流程有断点

❌ **图片支持有限** - Omnivore主要面向文本文章，图片/视频灵感仍需手动处理

### 预估工作量

- **初始搭建**：1小时
  - 安装Omnivore浏览器插件：5分钟
  - 注册Omnivore账号并熟悉功能：15分钟
  - 设计批处理Prompt模板：30分钟
  - 测试导出→处理→归档流程：10分钟

- **日常使用**：
  - **收集阶段**：每条5秒（点击浏览器插件）
  - **阅读标注**：在正常阅读中顺便高亮，零额外时间

- **每周处理**：15-20分钟
  - 从Omnivore导出高亮：2分钟
  - 粘贴到Claude Code并运行Prompt：3分钟
  - Claude处理时间：5-10分钟
  - 审查并微调：5分钟

### 方案B vs 方案A对比

| 维度 | 方案A | 方案B |
|------|-------|-------|
| 收集速度 | 需要复制粘贴（~30秒） | 一键保存（~5秒） |
| 工具数量 | 1个（Claude Code） | 2个（Omnivore + Claude） |
| 成本 | $0 | $0（Omnivore免费） |
| 数据掌控 | 100%本地 | Omnivore云端+本地归档 |
| 适合场景 | 灵感量<20条/周 | 灵感量20-50条/周 |

## 方案C：自建脚本 + API集成（深度自动化）

### 核心理念

构建全自动化数据管道，从收集到处理到归档全程无需手动干预。适合高频灵感收集者（>50条/周）或技术探索需求。

### 技术栈

- **Python脚本** - 数据抓取、处理、调度
- **Claude API** - 自动化内容分析和提取
- **存储层** - Markdown文件系统 或 Notion Database
- **调度系统** - Cron (Linux/Mac) 或 Task Scheduler (Windows)
- **数据源集成** - RSS订阅、浏览器书签API、邮箱IMAP

### 工作流程（全自动化）

1. **自动收集**
   - Cron定时任务每小时运行一次
   - 从RSS订阅源抓取新文章
   - 从浏览器书签同步新增条目
   - 从指定邮箱文件夹读取转发的内容

2. **自动处理**
   - 调用Claude API分析每条内容
   - 提取标题、摘要、关键词、应用场景
   - 按主题自动分类

3. **自动归档**
   - 生成Markdown文件保存到 `inspiration/YYYY-MM/`
   - 或写入Notion数据库（可选）
   - 更新索引文件

4. **自动提醒**
   - 每周五生成周总结并发送到邮箱
   - 每月生成月度精华推荐

### 需要开发的组件

**1. 内容抓取器 (collectors/)**
```python
# collectors/rss_collector.py
# 从RSS订阅源获取新文章

# collectors/bookmark_collector.py
# 从浏览器书签同步（Chrome/Firefox）

# collectors/email_collector.py
# 从邮箱IMAP读取转发内容
```

**2. Claude API处理器 (processor/)**
```python
# processor/claude_processor.py
# 调用Claude API提取信息
# 实现批量处理、错误重试、成本控制
```

**3. 存储适配器 (storage/)**
```python
# storage/markdown_storage.py
# 保存为Markdown文件

# storage/notion_storage.py (可选)
# 写入Notion数据库
```

**4. 调度器 (scheduler/)**
```python
# scheduler/main.py
# 主调度逻辑
# 协调收集→处理→存储流程
```

**5. 配置文件 (config.yaml)**
```yaml
sources:
  rss:
    - https://example.com/feed.xml
  email:
    server: imap.gmail.com
    folder: "Inspiration"

claude_api:
  key: "sk-ant-..."
  model: "claude-3-haiku-20240307"  # 使用更便宜的模型
  max_tokens: 1000

storage:
  type: "markdown"  # or "notion"
  path: "./inspiration/"

schedule:
  collect: "0 * * * *"  # 每小时
  weekly_summary: "0 18 * * 5"  # 每周五18:00
```

### 优点（3个）

✅ **完全自动化** - 收集、处理、归档全自动，零手动操作

✅ **可定制性强** - 可根据需求调整数据源、处理逻辑、存储方式

✅ **可扩展** - 轻松添加新数据源（Twitter API、GitHub Stars等）

### 缺点（3个）

❌ **开发工作量大** - 需要20-30小时初始开发，涉及多个组件

❌ **需要维护** - API变更、依赖更新、错误处理都需要持续维护

❌ **有运行成本** - Claude API按量计费，预估$5-15/月（取决于灵感量）

### 预估工作量

- **初始开发**：20-30小时
  - 环境搭建和依赖管理：2小时
  - RSS收集器开发：3小时
  - 浏览器书签同步：4小时
  - 邮箱收集器：3小时
  - Claude API封装：4小时
  - 存储层开发：3小时
  - 调度和错误处理：4小时
  - 测试和调优：5小时
  - 文档编写：2小时

- **日常使用**：完全自动，0时间投入

- **维护成本**：每月1-2小时
  - 检查日志和错误：30分钟
  - 调整配置（如新增RSS源）：30分钟
  - 依赖更新：1小时（每季度）

### 运行成本估算

**Claude API成本：**
- 假设每周收集50条灵感
- 每条消费约1000 tokens（输入+输出）
- 使用Claude 3 Haiku（最便宜）：$0.25/M tokens (输入), $1.25/M tokens (输出)
- 月度成本：50条/周 × 4周 × 1000 tokens × $0.001 ≈ **$5-10/月**

**服务器成本：**
- 本地运行：$0
- 云服务器（可选）：$5-10/月

**总计：$5-20/月**（取决于灵感量和部署方式）

### 方案C适用条件

**推荐使用场景：**
- ✅ 每周灵感 > 50条
- ✅ 有多个数据源需要整合
- ✅ 有一定Python开发能力
- ✅ 愿意投入初始开发时间
- ✅ 需要完全自动化流程

**不推荐场景：**
- ❌ 灵感量 < 20条/周（过度工程化）
- ❌ 不熟悉编程（维护成本高）
- ❌ 需求尚未验证（先用方案A/B试用2个月）
