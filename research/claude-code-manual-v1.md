## 能力概览

### 核心能力矩阵

| 能力类别 | 支持程度 | 适用场景 | 典型任务 |
|---------|---------|---------|---------|
| **文本文件处理** | ✅✅✅ | 批量编辑、格式转换 | Markdown整理、配置生成 |
| **代码执行** | ✅✅✅ | 脚本运行、命令行操作 | Python/JS脚本、Git操作 |
| **数据处理** | ✅✅ | 中小规模数据清洗分析 | CSV处理、JSON转换 |
| **Web交互** | ⚠️ | 仅限白名单域名 | API调用、文档获取 |
| **图片/多媒体** | ❌ | 仅可查看，不可编辑 | 图片分析（只读） |
| **实时/后台任务** | ❌ | 无法持续运行 | - |

### 三大核心优势

#### 1. 文件操作能力
```
✅ 文本文件：读取、创建、编辑、批量处理
✅ 二进制文件：图片查看、PDF阅读（最大32MB，100页）
✅ Jupyter Notebook：完整支持读写
✅ 目录操作：浏览、创建、搜索（Glob/Grep）
```

#### 2. 代码执行能力
```
✅ Bash命令：完整支持（ls、git、pip、npm等）
✅ Python/JavaScript：脚本执行、包管理
✅ Git操作：status、commit、push（遵循安全协议）
⚠️ 执行限制：默认2分钟超时，最长10分钟
```

#### 3. 智能代理能力
```
✅ 任务分解：将复杂需求拆分为可执行步骤
✅ 代码理解：分析代码库、识别问题
✅ 自动化：生成脚本、批量操作
✅ 专用代理：Explore（探索代码）、Task（复杂任务）
```

## 限制说明

### 三大核心限制

#### 1. 网络访问限制 🌐
```
限制：只能访问白名单域名
影响：无法直接访问大部分网站
已知可访问：api.anthropic.com, github.com, pypi.org, npmjs.com

替代方案：
→ 手动提供内容
→ 使用WebFetch工具
→ 本地下载后处理
```

#### 2. 执行时间限制 ⏱️
```
限制：默认2分钟，最长10分钟
影响：长时间任务可能超时
适合：单个任务<5分钟

替代方案：
→ 分解为多个小任务
→ 保存中间结果
→ 批量处理策略
```

#### 3. 资源限制 💾
```
限制：
- 文件大小：建议<1MB
- PDF文件：最大32MB，100页
- GPU算力：按小时/周限制
- 内存/CPU：有限

影响：不适合大数据、计算密集型任务

替代方案：
→ 分批处理
→ 简化算法
→ 云端计算
```

### 场景适配快速判断

**✅ 适合的场景**（推荐使用）：
1. 文档批量处理（Markdown、配置文件）
2. 数据清洗整理（<10000行CSV/JSON）
3. 代码/脚本生成（自动化脚本、样板代码）
4. 项目初始化（目录结构、配置文件）
5. 信息提取汇总（文本分析、数据提取）
6. 代码审查重构（安全检查、命名优化）
7. Git工作流管理（提交、PR描述）
8. 配置文件生成（Docker、CI/CD）

**❌ 不适合的场景**（寻找替代）：
1. 实时数据处理 → 使用云服务
2. 大规模爬虫 → Scrapy本地运行
3. 多媒体编辑 → 在线工具/本地软件
4. 高频API调用 → 部署到服务器
5. 复杂前端开发 → 本地开发环境
6. 数据库管理（生产） → DBeaver等专用工具
7. 机器学习训练 → Google Colab/SageMaker
8. 系统级运维 → Terraform/Ansible

**⚠️ 边界场景**（谨慎使用）：
- Web抓取：小规模（<50页）可行
- 数据分析：中等规模（<10000行）可行
- 多步workflow：分段执行（<10步）可行
- Git复杂操作：避免交互式命令

### 5个问题快速判断

```
1. 任务能否在5分钟内完成？
   否 → 需要分解任务

2. 是否需要网络访问非白名单域名？
   是 → 考虑替代方案

3. 是否需要持续运行或后台服务？
   是 → 不适合Claude Code

4. 是否处理二进制文件（图片/视频/音频）？
   是 → 不适合Claude Code

5. 数据量是否<100MB，记录数<10000？
   否 → 需要分批或不适合

✅ 如果5个问题都通过，则非常适合Claude Code！
```

详细限制清单见：**[claude-code-limitations.md](./claude-code-limitations.md)**

## 最佳实践

### 黄金5原则

#### 1. 分解任务 📋
```
大任务 → 小步骤
每步 <5分钟
保存中间结果
可从任意点恢复
```

**示例**：
```
❌ 错误：「处理100个CSV文件并生成报告」

✅ 正确：
步骤1：处理前10个文件 → temp/batch1.json
步骤2：处理第11-20个文件 → temp/batch2.json
...
步骤10：汇总所有结果 → final_report.md
```

#### 2. 明确输入输出 📝
```
清晰定义：
- 输入文件路径和格式
- 处理步骤（具体动作）
- 输出文件路径和格式
- 预期结果数量
```

**标准Prompt模板**：
```markdown
**目标**：[1句话描述]

**输入**：
- 文件：[路径]
- 格式：[说明]

**步骤**：
1. [动词开头的具体步骤]
2. [...]

**输出**：
- 文件：[路径]
- 格式：[说明]

**注意事项**：
- [错误处理]
- [边界情况]

请逐步执行，每步等待确认。
```

#### 3. 逐步验证 ✓
```
执行步骤1 → 检查输出 → 确认
执行步骤2 → 检查输出 → 确认
...
```

**验证检查点**：
- 文件是否生成？
- 大小是否合理？
- 抽样数据质量
- 数量是否符合预期

#### 4. 控制复杂度 📊
```
复杂度指标：
□ 文件数量 <100个/批
□ 数据行数 <10000行/批
□ 文件大小 <100MB/批
□ 处理时间 <5分钟/步
□ 循环次数 <1000次
```

#### 5. 保存中间结果 💾
```python
# ✅ 每步保存
data = load()
save('temp/step1.json')

processed = process(data)
save('temp/step2.json')

final = finalize(processed)
save('output/final.json')
```

### 防卡顿4技巧

#### 技巧1：控制搜索次数
```
单任务网络搜索 ≤3次
优先使用已知信息
批量搜索合并为1次
搜索结果保存本地
```

#### 技巧2：分批处理数据
```python
# ✅ 分批处理
batch_size = 100
for i in range(0, len(files), batch_size):
    batch = files[i:i+batch_size]
    process_batch(batch)
    save(f'temp/batch_{i}.json')
```

**分批大小建议**：
- CSV：1000-5000行/批
- JSON：50-100文件/批
- 图片：20-50个/批
- API：10-20个/批

#### 技巧3：设置超时和重试
```bash
# Bash重试机制
for i in {1..3}; do
    curl -f "https://api.example.com/data" && break
    sleep $((2**i))  # 指数退避：2s, 4s, 8s
done
```

#### 技巧4：使用流式处理
```python
# ✅ 流式读取大文件
for chunk in pd.read_csv('huge.csv', chunksize=1000):
    process(chunk)
    save_chunk(chunk)
```

## 故障排查

### 6大常见问题速查

#### 问题1：执行卡住/无响应
```
症状：长时间无输出
原因：任务太复杂/网络超时/数据过大

快速修复：
1. 简化任务（减小批次）
2. 检查网络依赖 → 改用手动提供
3. 分解为更小步骤
4. 添加进度输出
```

#### 问题2：网络请求失败
```
症状：403 Forbidden / Connection timeout
原因：域名不在白名单/网络不稳定/API限流

快速修复：
1. 域名不可达 → 手动提供内容
2. 超时 → 增加重试机制
3. 限流 → 添加延迟（2秒/次）
```

#### 问题3：文件操作失败
```
症状：FileNotFoundError / PermissionError
原因：路径错误/权限不足/格式不支持

快速修复：
1. 路径错误 → ls 确认，使用相对路径
2. 权限不足 → 操作 ~/ 用户目录
3. 格式不支持 → 使用转换库
```

#### 问题4：输出不符合预期
```
症状：结果格式错误/数据缺失
原因：Prompt不清晰/数据格式问题/逻辑误解

快速修复：
1. 澄清需求（使用标准模板）
2. 提供输出示例
3. 逐步验证中间结果
4. 检查边界情况
```

#### 问题5：包/库无法使用
```
症状：ModuleNotFoundError / ImportError
原因：包未安装/包名错误/版本冲突

快速修复：
1. pip install package_name
2. 检查包名拼写
3. 使用内置库替代
4. 生成requirements.txt
```

#### 问题6：Git操作失败
```
症状：push failed / merge conflict
原因：分支命名/网络问题/权限/冲突

快速修复：
1. 分支名符合规范（claude/xxx-sessionid）
2. Push重试（指数退避）
3. 先pull再push
4. 避免复杂merge/rebase
```

### 应急处理流程

**任务卡住时**：
```
Step 1: 保存已完成部分 → 输出到文件
Step 2: 标记断点 → 记录进度
Step 3: 分析原因 → 任务/网络/数据/Token
Step 4: 调整策略 → 简化/分段/去网络依赖
Step 5: 从断点继续
```

**输出错误时**：
```
Step 1: 停止执行 → 保存错误结果
Step 2: 检查输入 → 数据格式是否正确
Step 3: 检查Prompt → 是否有歧义
Step 4: 小范围测试 → 1-2个样本验证
Step 5: 全量执行 → 逻辑正确后处理全部
```

### 诊断决策树

```
任务失败？
│
├─ 执行卡住
│  ├─ >10分钟无输出 → 任务太复杂，需分解
│  ├─ Token快速增长 → 大文件，改用分批
│  └─ 网络请求中 → 改用手动提供
│
├─ 文件错误
│  ├─ FileNotFoundError → ls确认路径
│  ├─ PermissionError → 操作用户目录
│  └─ 格式不支持 → 使用转换库
│
├─ 输出错误
│  ├─ 格式不对 → 提供输出示例
│  ├─ 数据缺失 → 检查输入数据
│  └─ 逻辑错误 → 小样本测试
│
├─ 网络错误
│  ├─ 域名不可达 → 手动提供数据
│  ├─ 超时 → 设置重试
│  └─ 限流 → 添加延迟
│
└─ 依赖错误
   ├─ 模块未找到 → pip install
   ├─ 命令不存在 → 使用内置替代
   └─ 版本冲突 → 检查兼容性
```
